Версия 5.1 — 18.11.2026. ДВЕ КАМЕРЫ, СТАНДАРТНЫЙ V4L2. Патчи 247–438.

1. РЕЗЮМЕ
---------
Плата Orange Pi Zero 3W (Allwinner A733) в вендорском BSP не видела MIPI-камеры:
«chip found is not target chip», 8+ дней диагностики. Результат проекта — V4L2-драйвер
IMX219 (статус ALPHA): ДВЕ камеры одновременно (/dev/video0, /dev/video8), Bayer RAW10
через стандартный стриминг v4l2-ctl / GStreamer, 6 режимов разрешения, цифровой кроп
с автобиннингом, прямые контролы экспозиции/усиления/fps.
Примечание: вывод «hardware defect» в старом отчёте от 31.10 (см. историю коммитов)
опровергнут — дефекта железа нет, см. раздел 3.

2. РЕЖИМЫ И FPS (измерено)
-------------------------
Одиночная камера, реальные замеры (примерно): 3280x2464 ~19 | 1920x1080 ~46 |
1640x1232 (полный FOV, апп. биннинг 2x2) ~41 | 1280x960 ~52-54 | 1280x720 ~71 |
640x480 ~104 fps. Максимальные значения таблицы в README получены по формуле
(константа K; для 1280x960 она занижена — фактически выдаёт больше расчётного).
Две камеры одновременно: подтверждено 2x59.9 fps в 1280x720 (CAM1 1797 + CAM2 1796
кадров за 30 с, 15.11). Dual на полном кадре не измерялся (лимит линка 21 fps/камера).

3. КАК ЭТО БЫЛО (наблюдения, не единственная причина)
----------------------------------------------------
Одна из найденных проблем: sunxi_mipi_g_mbus_config() получал num_data_lanes = 0
(сенсор-модуль собран под пре-5.11 заголовки) → PHY на 1 лан → поток резался, тысячи
ECC. PATCH361 форсит 2 лана. Остальные причины перечислены патчами 311–411
(см. PATCHES.md). Вендорский ISP-пайплайн мы не использовали: кадры идут через
TDM RXk pkg-буферы → V4L2 vb2 (патчи 412–438); штатный ISP в этом BSP не нужен.
«Камеры исправны» — проверялось отдельно на Raspberry Pi 5 (обе отдали картинку).

4. ИСТОРИЯ КРАТКО (дни проекта)
------------------------------
Дни 1-9: «мёртвый приёмник». Аудит PHY/парсера/ISP/TDM, регистровые дампы, TPG.
День 10: ПЕРВОЕ ИЗОБРАЖЕНИЕ (обход TDM→/dev/mem).
День 12: ЖИВОЕ ВИДЕО на HDMI, ~40 fps (livec: debayer+AWB+AE+gamma).
День 13: 2x2 биннинг (полный FOV), plain packed RAW10 (PATCH395, ушёл дрейф).
День 14: 60 fps; git-репо на плате; разбор tdm200/top_reg.
День 17: ДВЕ КАМЕРЫ ОДНОВРЕМЕННО (PATCH411: ISP0 input select), 2x59.9 fps.
Дни 18-19: V4L2 vb2-доставка (412-416), контролы IMX219 (417-420: 0x41701-04),
  свой G_PARM/S_PARM (421), геометрия TDM для анпакера (422), realloc буферов (423),
  flush/quiesce (424), payload W*H*2 (425), K fps↔frame-length (426),
  снимок в IRQ + invalidate (427-429, ушли stale-line полосы), тихие логи (430),
  честные ENUM (431), BG10↔RG10 на границе ioctl (432), пер-мод интервалы (434),
  клэмп выдержки (435), универсальный кроп+биннинг (436), BA81 8-бит (438).

5. АРХИТЕКТУРА
-------------
sensor -> MIPI PHY (2 лана, PATCH361) -> CSI parser -> TDM RXk pkg-буфер (DDR,
некешируемый) -> V4L2 vb2 (распаковка RAW10->16 бит в ядре, чтение через phys_to_virt
со снимком кадра в IRQ, PATCH427/428) -> /dev/video0, /dev/video8.
Форматы: BG10 (10 бит в 16-бит контейнере, BGGR) и BA81 (8 бит). Захват MPLANE
(поэтому ffmpeg не видит устройство). Кроп S_SELECTION; биннинг 2x2 автоматически,
если запрошенный размер <= половины окна.

6. МЕХАНИКА ДВУХКАМЕРНОСТИ
--------------------------
TDM rx_k — тапы общего домена входов ISP0. Какой парсер в слоте k, программирует
vinc при старте стрима: csic_isp_input_select(...) -> CSIC_ISP0_IN0 + 16k.
vinc с tdm_rx_sel=0 → слот 0/парсер csi0; с tdm_rx_sel=1 → слот 1/парсер csi1.
Без программирования всё падает в слот 0 («только через rx0»).

7. ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ
------------------------
- Выдержка ограничена длиной кадра: чем выше fps, тем короче макс. экспозиция
  (драйвер урезает, запомненное значение переприменяется при смене fps).
- Устройство открывается эксклюзивно: контролы меняет только держащий процесс.
- Аппаратного AWB в IMX219 нет — программно после дебайера.
- ffmpeg (-f v4l2) устройство не видит: ядро объявляет только multiplanar-захват.
- GStreamer 1.20: BG10 не поддерживается; проверен BA81 через bayer2rgb.
- OpenCV ожидается совместимым (CAP_V4L2, CONVERT_RGB=0), на плате не проверялся
  (OpenCV не установлен).
- Предупреждение "sunxi-iommu-v2.c" при открытии безвредно (вендорский IOMMU).
- Debug-логи выключены: echo 1 > /sys/module/vin_io/parameters/vin_debug.
- Буферы vb2 некешируемые: чтение 720p-кадра 1.9 мс против 1.0 мс из обычной
  памяти (~11% ядра на 60 fps); кеширование не включали из-за риска порчи кадров.
- Dual подтверждён только в 1280x720 (2x59.9); dual на прочих режимах не измерялся.

8. ПРОИЗВОДИТЕЛЬНОСТЬ И ЗАПАСЫ
------------------------------
Линки: 2 лана x 456 МГц на камеру (~1.8 Гбит/с) — до 21 fps на полном кадре (даташит).
TDM/DDR: 2x60fps @720p ≈ 230 МБ/с — свободно. CPU: распаковка+стриминг ~11% ядра
на камеру @60fps. Запись: несжатый RAW на microSD невозможен (424 МБ/с на 2x21fps
full-res); путь — VPU Cedar H.264 после софтверного/GPU дебайера; 2x1080p@30 —
первая веха рекордера.

9. ПРИМЕНЕНИЯ
-------------
Драйвер универсален: стерео/VR180 (два глаза), робототехника/дроны, машинное
зрение, SLAM/навигация. Также потенциально покрывает Orange Pi 4 Pro (тот же SoC
A733/sun60iw2 — проверка совместимости не проводилась).
Для VR-стерео: у клонов IMX219 нет FSIN — синхронизация программная (одновременный
старт + таймстемпы), как в коммерческих VR180 на этом сенсоре.
